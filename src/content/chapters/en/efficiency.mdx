A smart model that is slow and memory-hungry is, in practice, barely usable.
Every question costs time and electricity, and few machines can run it at all.
So this chapter looks at tricks that keep the answers essentially the same while making the same model run faster and lighter.

## The KV cache: remember what you've made

Text is produced one word at a time.
Each time, attention revisits all the words so far — and recomputing the past from scratch every round is plainly wasteful.

We can call it waste with confidence because the past words' information (their attention keys and values) never changes afterward.
Recall the causal mask from the Transformer chapter.
Past words never look at the future, so nothing appended later can alter what was computed for them.
If it never changes, compute it once, jot it down, and reuse it.
Only the new word's share needs computing.
That jotted-down note is the **KV cache**.

<KVCacheDemo client:visible lang="en" />

Move the slider and you'll see that the longer the text, the more explosively "recompute everything" grows, and the wider its gap with "reuse the cache" becomes.
Stop redoing the sums every time a sentence is added to the textbook; keep the finished work on file and reuse it as is.
That is the trick.
In exchange, the memory to hold the notes grows a little.

## Quantization: hold the weights coarsely

Next, a trick that shrinks the memory itself.
A computer stores every number as a bundle of **bits** — the smallest units of data, each a 0 or a 1 — and more bits means finer detail.
Model weights are normally stored as fine-grained decimals using a generous number of bits.
Rounding them coarser and storing them in fewer bits is **quantization**.

<Quantization lang="en" />

Like turning 3.14159… into 3.1, a little precision is sacrificed and the memory needed for storage drops dramatically.
Going from 16 bits to 4 bits cuts the weights' footprint to roughly one quarter.
That is what lets fairly large models run on small hardware — laptops, even phones.
The craft is in choosing what to round, and how coarsely, so the loss of accuracy stays small.

## FlashAttention: computing without building the giant table

Attention was a calculation that builds an all-words × all-words score table.
As text grows, that table stretches in both directions and squeezes memory.

<AttentionMemory lang="en" />

The method called **FlashAttention** never builds the giant table whole; it splits the work into small blocks and processes them in order.
Only one block is ever held at a time.
The answer that comes out is exactly the same — yet the memory needed drops sharply and the whole thing runs faster.
The seed of the speedup is arranging the memory reads and writes to fit what GPUs do best.

## More still: head sharing and speculative decoding

The cost-cutting toolbox goes on.

- **MQA / GQA**: several attention heads share their keys and values. What is shared no longer needs its own space, so the KV cache shrinks.
- **Speculative decoding**: a small, fast draft model proposes the next several words at once, and the real, large model checks them in one batch. When the draft is right, everything advances in one leap — speed without giving up quality. The draft gets written first; the teacher grades it all at once.

These appear across many implementations — GPT, Llama, Claude, Gemini, Mistral, Qwen — to bring inference costs down.

Here the stack of mechanisms reaches a resting point.
