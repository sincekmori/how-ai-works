Extracting information from free text was endless whack-a-mole.
So we flipped the idea: have the reply come back in an easy-to-extract shape from the start.
The leading such shape is JSON.
Let's see what it actually is.

## What a "fixed shape" looks like

Write "Tokyo tomorrow: sunny, up to 28°C" in a fixed shape, and you get this:

```json
{
  "city": "Tokyo",
  "condition": "sunny",
  "temperature": 28,
  "humidity": 45
}
```

This is **JSON**.
The world has several fixed shapes, and this is the most widely used standard among them.
It looks a bit forbidding, but the rule is simple.
Line up **keys** and **values**, paired by colons — that's all.
The key `"city"` with the value `"Tokyo"`, the key `"temperature"` with the value `28`, and so on.

Values come in kinds.
Quoted things like `"Tokyo"` are strings; bare numbers like `28` are numbers.
You can also put in an array — an ordered list in square brackets, like `["poker", "shogi"]`.
Keys and strings are always wrapped in `"` (double quotes).

## Pinpoint by key

The blessing of JSON is that a program can use a key to pull out a value with pinpoint accuracy.

Here is how, up front.
A program stores received JSON in a named container (called a variable).
Since this is weather data, call it weather.
Then writing weather["city"] — container name, then key in brackets — pulls out just that key's value.

Here lies the most important intuition:
the key names are fixed; only the values change.
Sunny or rainy, the key `"condition"` is always the same.
So the program can aim for "the value under `condition`" with the same one line of code, every time.
Nothing like hunting for numbers in free prose — reliable, no wobble.

Bigger, more tangled JSON is coming in later chapters.
The way of reading it stays the same.
However deep it nests, follow the keys and look only at the value you want.
This key-following way of reading keeps paying off from here on.

## For machines, not for people

One easy misunderstanding to clear up.
JSON is a shape for machines' ease of reading; human readability is not its first concern.
That is why keys are normally written in plain unaccented letters and digits rather than in everyday language (programs treat keys like variable names).
Spaces and newlines mean nothing to the machine either way, so JSON often travels tightly squeezed.

A program-friendly shape is now in hand.
What remains is the main event.
How do you get the model to answer in this JSON?
Is asking nicely — "please reply in JSON" — enough?
