前の章で、自由な文から情報を抜くのは終わりのないモグラたたきだと分かりました。
そして、「最初から取り出しやすい形で返してもらえばいい」という発想にたどり着き、その形の名が **JSON** だと知りました。
この章では、その JSON の正体を、ちゃんと見ていきます。

## 「決まった形」で書くと、こうなる

前の章で見たとおり、自由な文章はプログラムにとって、毎回かたちが違う扱いにくいデータでした。
その反対、つまり **あらかじめ決めた形** にそろえると、どうなるのか。
「東京の明日は晴れ、気温は 28 度」を、決まった形で書くと、こうなります。

```json
{
  "city": "Tokyo",
  "condition": "sunny",
  "temperature": 28,
  "humidity": 45
}
```

これが **JSON（ジェイソン）** です。
世の中には「決まった形」がいくつもありますが、その中でいちばん広く使われている標準がこれです。
見た目は少しとっつきにくいですが、ルールはとても単純。
**鍵（キー）** と **値** を、コロンでペアにして並べるだけです。
`"city"` という鍵に `"Tokyo"` という値、`"temperature"` という鍵に `28` という値、という具合に。

値には種類があります。
`"Tokyo"` のように引用符でくくったものは **文字列**、`28` のような数は **数値**。
ほかに、`["ポーカー", "将棋"]` のように角かっこで並べた **配列**（順番つきのリスト）も入れられます。
鍵と文字列は、かならず `"`（ダブルクオート）でくくります。

## 鍵で、ねらいうち

JSON のうれしいところは、**プログラムが鍵をたよりに、値をピンポイントで取り出せる** ことです。

やり方を先に見ておきましょう。
プログラムは、受け取った JSON を、名前をつけた入れもの（**変数** といいます）にしまって使います。
ここでは、天気のデータなので weather という名前にしましょう。
あとは weather["city"] のように「入れものの名前［鍵］」と書くだけで、その鍵の値だけを取り出せます。
下で、実際に鍵をクリックして確かめてみてください。

<JsonEye client:visible />

ここに、いちばん大事な感覚があります。
**鍵の名前は固定、値だけが変わる。**
天気が晴れでも雨でも、`"condition"` という鍵はいつも同じ。
だからプログラムは「`condition` の値がほしい」と、毎回おなじ書き方でねらえます。
自由な文章から数字を探すのとは大違いで、確実で、ぶれません。

これから、もっと大きくて複雑な JSON が出てきます。
でも見方は今と同じ。
どんなに入り組んでいても、鍵をたどって、ほしい値のところだけ見ればいいのです。
この「鍵をたどる読み方」が、この先ずっと効いてきます。

## 人のためではなく、機械のために

最後に、勘ちがいしやすい点を。
JSON は「機械にとっての読みやすさ」のための形であって、「人にとっての読みやすさ」が第一ではありません。
だから鍵は、日本語ではなく英数字で書くのがふつうです（プログラムでは鍵を変数の名前のように扱うから）。
スペースや改行は、あってもなくても機械には同じ意味なので、送るときはぎゅっと詰めた形になることも多いです。

さて、プログラムに優しい形が手に入りました。
残るのは、いよいよ本題。
**どうやって、モデルにこの JSON で答えさせるか** です。
次の章では、まず素朴に「JSON で返して」と頼んでみて、それがどこで綻ぶのか、そして最終的にどうやって形を保証するのかを見ていきます。
