自由な文から情報を抜くのは、終わりのないモグラ叩きでした。
そこで、最初から取り出しやすい形で返してもらう、という発想に切り替えたのでした。
その形の代表が JSON です。
まず、この形の正体を見ておきます。

## 「決まった形」で書くと、こうなる

「東京の明日は晴れ、気温は 28 度」を、決まった形で書くと、こうなります。

```json
{
  "city": "Tokyo",
  "condition": "sunny",
  "temperature": 28,
  "humidity": 45
}
```

これが **JSON**（ジェイソン）です。
世の中には決まった形がいくつもありますが、その中で一番広く使われている標準がこれです。
見た目は少しとっつきにくいものの、ルールは単純です。
**鍵**（キー）と **値** を、コロンでペアにして並べるだけ。
`"city"` という鍵に `"Tokyo"` という値、`"temperature"` という鍵に `28` という値、という具合です。

値には種類があります。
`"Tokyo"` のように引用符でくくったものは文字列、`28` のような数は数値です。
`["ポーカー", "将棋"]` のように角かっこで並べた配列（順番つきのリスト）も入れられます。
鍵と文字列は、必ず `"`（ダブルクオート）でくくります。

## 鍵で、狙い撃ち

JSON のありがたみは、プログラムが鍵を頼りに、値をピンポイントで取り出せることです。

やり方を先に見ておきます。
プログラムは、受け取った JSON を、名前をつけた入れもの（変数といいます）にしまって使います。
天気のデータなので、ここでは weather という名前にします。
後は weather["city"] のように「入れものの名前［鍵］」と書くだけで、その鍵の値だけを取り出せます。
下のデモで、鍵をクリックして確かめてみてください。

ここに、一番大事な感覚があります。
鍵の名前は固定で、値だけが変わる。
天気が晴れでも雨でも、`"condition"` という鍵はいつも同じです。
だからプログラムは「`condition` の値がほしい」と、毎回同じ書き方で狙えます。
自由な文章から数字を探すのとは大違いで、確実で、ぶれません。

この先の章では、もっと大きくて複雑な JSON が出てきます。
それでも見方は同じです。
どんなに入り組んでいても、鍵を辿って、ほしい値のところだけ見ればいい。
この鍵を辿る読み方が、この先ずっと効いてきます。

## 人のためではなく、機械のために

勘違いしやすい点を一つ。
JSON は機械にとっての読みやすさのための形であって、人にとっての読みやすさが第一ではありません。
だから鍵は、日本語ではなく英数字で書くのが普通です（プログラムでは、鍵を変数の名前のように扱うからです）。
スペースや改行は、あってもなくても機械には同じ意味なので、送るときはぎゅっと詰めた形になることも多いです。

これで、プログラムに優しい形が手に入りました。
残るのは本題です。
モデルに、この JSON で答えてもらうには、どうすればよいのでしょうか。
「JSON で返して」と頼むだけで、うまくいくものでしょうか。
